# 토익 단어 객관식 앱 설계

작성일: 2026-11-15

## 의도와 이유
토익에 자주 나오는 단어 약 5000개를 폰에서 틈날 때마다 객관식으로 풀며 외운다.
하루 300문제를 풀고, 자주 틀린 단어일수록 더 자주 출제되게 해서 약한 단어를 집중 보강한다.
사용자 본인 한 명이 쓰는 개인용 앱이다.

## 목표
- 폰에서 틈날 때 몇 문제씩 끊어 풀 수 있다. 앱을 닫았다 열어도 오늘 진행 상황이 이어진다.
- 영어 단어를 보고 한국어 뜻을 고르는 5지선다 객관식. 1~4번은 뜻 보기(정답 1개 + 오답 3개), 5번은 항상 "모르겠다"로 고정된다. (사용자 요청, 2026-11-15)
- 하루 300문제. 5000개 전체에서 출제하되, 많이 틀린 단어일수록 뽑힐 확률이 높다.
- 인터넷 없이 동작한다(오프라인).
- 토익 빈출 단어 약 5000개와 빈출 뜻을 포함한다.

## 비목표
- 계정, 로그인, 서버, 기기 간 동기화.
- 앱스토어 배포, 네이티브 앱 빌드.
- 발음/음성, 예문 학습, 스펠링 입력 문제(이번 범위 밖).
- 한국어→영어 방향 문제.

## 안티 목표 (기술적으로 돌아가도 실패인 경우)
- 같은 날 같은 단어가 두 번 나옴.
- 폰 브라우저를 닫거나 새로고침했더니 오늘 진행 상황이나 오답 기록이 사라짐.
- 정답 보기가 오답 보기 3개 중 뜻이 사실상 같은 말이라 정답이 둘로 보임.

## 제약
- 사용자가 직접 설치하거나 빌드하는 단계가 없어야 한다. HTML/CSS/JS 정적 파일만 쓴다.
- 폰 브라우저(세로 화면, 한 손 조작)가 주 사용 환경이다.
- 단어 데이터는 제가 만든다. ETS 공식 목록이 아니라 빈출 기준으로 만든 것이라 일부 뜻이 책과 다를 수 있다.

## 접근 방식 (검토한 안)
- **A. 웹앱(홈 화면 추가, PWA) — 선택.** 정적 파일과 브라우저 저장소. 설치·빌드 불필요, 오프라인 가능, 수정이 바로 반영된다. 단점은 브라우저 저장 데이터를 지우면 기록이 사라지는 것이며, 내보내기/가져오기로 대응한다.
- B. 웹앱 + 서버(동기화). 기기를 바꿔도 기록이 유지되지만 서버와 로그인이 필요해 개인용으로는 과하다.
- C. 네이티브 앱(Flutter/React Native). 폰에 설치하려면 빌드 환경과 서명이 필요하고 수정할 때마다 재설치해야 한다. 이번 용도에서 A보다 나은 점이 거의 없다.

사용자가 C에 끌렸으나 추천을 듣고 A를 선택했다.

## 사용자가 정한 것
- 하루 300문제, 영어→한국어 객관식.
- 많이 틀린 단어일수록 출제 확률이 높아진다.
- 하루에 300개를 다 못 풀면 남은 문제는 이월하지 않는다. 다음 날은 새로 300개로 시작한다.
- 폰에서 틈날 때 나눠서 푼다.
- 단어는 토익 빈출 단어와 빈출 뜻 위주.

## 제 판단 (사용자가 아직 검토하지 않은 부분)
- 화면: 상단에 진행 현황(오늘 N/300, 맞은 수, 틀린 수), 가운데 영어 단어, 아래 뜻 보기 4개와 그 밑에 고정된 5번 "모르겠다". "모르겠다"를 누르면 틀린 것으로 처리해 가중치를 올리고 정답을 보여준다(제 판단: 찍어서 맞히는 것보다 모르는 걸 솔직히 표시하는 쪽을 약한 단어 신호로 쓰는 게 목적에 맞다). 보기를 누르면 즉시 정답/오답을 표시하고 다음 문제로 넘어간다.
- 오답 보기 3개는 같은 품사의 다른 단어 뜻에서 뽑는다.
- 단어마다 빈출 뜻 1~2개를 담는다.
- 출제 가중치: 모든 단어의 기본 가중치는 1. 틀리면 올라가고 맞히면 조금씩 내려가며, 상한과 하한을 둔다. 틀린 적 없는 단어도 계속 출제된다. 구체적인 증감 수치는 구현 때 정한다.
- 오늘 출제할 300개는 하루의 첫 실행 때 가중 랜덤으로 한 번에 뽑아 저장한다(중복 없음). 이렇게 하면 앱을 닫았다 열어도 같은 문제 목록이 이어진다.
- "하루"의 기준은 기기의 날짜가 바뀌는 자정으로 한다.
- 데이터 저장은 브라우저의 로컬 저장소(localStorage 또는 IndexedDB). 기록 내보내기/가져오기 버튼을 둔다.
- 사용자가 단어 뜻을 앱에서 고칠 수 있게 하는 기능은 선택 사항으로, 후순위로 둔다.

## 검토 후 추가로 정한 것 (제 판단)
- 단어 데이터는 빌더(Claude)가 직접 생성한다. 기존 파일은 없다. 한 단어에 품사 1개, 대표 뜻 1개(필수), 보조 뜻 0~1개를 담는다. 구현 후 중복·누락·품사 오류를 스크립트로 검사한다.
- 정답은 항상 대표 뜻이다. 오답 보기는 다른 단어의 대표 뜻에서만 뽑는다(보조 뜻은 쓰지 않는다). 보조 뜻은 정답 확인 시 함께 보여준다.
- 정답과 뜻이 사실상 같은 오답을 막는 방법: 단어마다 유의어 그룹 태그를 달고, 같은 그룹의 단어는 서로의 오답 후보에서 제외한다. 태그는 데이터 생성 때 붙이고 검증 스크립트로 한 번 점검한다.
- 오늘 300문제 목록은 만들어진 날짜에 묶인다. 자정을 넘겨 풀고 있어도 그 세션은 끝까지 풀 수 있고, 앱을 다시 열 때 날짜가 바뀌었으면 새 300개를 뽑는다. 앱을 열지 않은 날은 그냥 건너뛴다.
- 한 단어는 하루에 한 번만 나오고 재도전은 없다. 가중치는 그 한 번의 답으로 갱신한다.
- 가져오기는 전체 교체 방식이다. 실행 전에 "현재 기록이 대체됩니다" 확인을 받는다.

## 빌더에게 맡기는 것
- 파일 구성, 데이터 형식(JSON 등), 단어 데이터를 나눠 만드는 방법.
- 가중치 증감 수치와 상하한.
- 디자인(색, 글꼴, 정오답 표시 방식)과 오프라인 캐시 구현 세부.
